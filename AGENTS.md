# Project instructions

## General behavior

- Be direct, concise, and task-focused.
- Avoid generic AI-style phrasing.
- Do not use filler, over-explaining, or exaggerated wording.
- Do not make assumptions.
- If required information is missing, ask clear questions before continuing.
- Do not add fallback logic unless explicitly requested.
- Prefer simple, explicit solutions over complex ones.

## Report writing

- Write in clear academic English.
- Use short sentences.
- Avoid vague phrases such as:
  - “Il est important de noter que”
  - “Dans le cadre de”
  - “Cette approche vise à”
  - “Il convient de souligner que”
  - “De manière générale”
- Prefer concrete wording.
- Stay factual and specific.
- Do not inflate the text.
- Do not repeat the same idea.
- Respect ISIMM report rules:
  - English language
  - Maximum 80 pages excluding annexes
  - Times New Roman 12
  - Line spacing 1.5
  - Margins 2.5 cm
  - Numbered sections: 1, 1.1, 1.1.1
  - Figure captions below figures
  - Table captions above tables
  - References at the end, sorted alphabetically

## Code generation

- Generate short, readable code.
- Keep code straight to the point.
- Do not add fallback behavior unless requested.
- Do not add unnecessary abstractions.
- Do not add comments unless they clarify non-obvious logic.
- Do not silently invent missing variables, endpoints, schemas, or file paths.
- If inputs, types, expected output, framework, or constraints are missing, ask first.
- Match the existing project style.
- Modify only the requested files or functions.
- Avoid broad refactors unless explicitly requested.
- Explain changes briefly after the code.
